2. Parse source & confirm schema

No silent format guessing when ambiguous
Header row is required because field selection is name-based. For Concordance DAT, the parser supports FE (þ) field qualifiers, DC4 / ASCII 20 field separators, embedded CR/LF inside qualified fields, and doubled FE as a literal FE.

3. Pairing & update configuration

Pairing rule: target Control Number must end with the configured suffix; its source is the exact remaining string. No trimming, case folding, fuzzy matching, or “best guess” pairing is performed. Case/Unicode look-alike collisions are treated as blocking ambiguity.
