Processing order & exception policy
  1. Read. Each record is read from the original DAT. Every output field is computed from original source columns only; one rule never reads another rule's result.
  2. Delivery Work. A rule applies to all documents, or only to members of the selected group. Outside that scope the selected source column is copied unchanged.
  3. Scrub last. For documents in a target group, Scrub writes a blank and that cell is not converted or validated. Keep retains the Delivery Work result. Documents in no group are not scrubbed.
  4. Exceptions block the whole file. An unmapped value, a blank where blanks are not allowed, an invalid date, a non-integer page count or a missing parent is listed by document. Saving stays blocked until the source or rule is corrected and preflight runs again. No partial or best-effort output is written.
  5. Nothing is inferred. No time-zone conversion, no blank-to-N, no blank page count to 1, no relationships from Bates numbers, no trimming or case changes.
  6. Any change resets approval. Changing the source, a target list, a field, a rule, a group or the ticket text clears the preflight, approval, PASS and any pending download.
  7. PASS means the saved file was re-read. The entire saved DAT is compared with the original and the approved plan before PASS is shown.
