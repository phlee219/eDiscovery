# 테스트 결과와 검증 한계

- 대상 버전: `1.0.0-rc.2`
- 실행일: 2026-10-06
- 환경: Windows 11 Pro, Node.js v24.19.0(개발자 런타임), Google Chrome 154.0.8037.98 및 Microsoft Edge 154.0.4258.62(시스템 설치, headless), Playwright(기존 개발자 설치)

테스트 통과는 "구현이 테스트한 조건에서 의도대로 동작한다"는 뜻입니다. 고객 납품 안전성 전체를 인증하지 않습니다.
실제 납품 전에는 사람이 규칙과 결과를 검토해야 합니다.

## 1. 단위·보안 테스트 — 59 / 59 통과

node --test tests/core.test.cjs tests/security.test.cjs

## 2. 실제 브라우저 테스트 — 29 / 29 통과 (Chrome 연속 2회 + 최종 1회, Edge 1회)

```bash
node tests/browser.test.cjs
```

Edge로 실행할 때는 `CHROME_PATH`에 `msedge.exe` 경로를 지정합니다. 실제 브라우저에서 화면 조작, Blob Worker, CSP, 파일 선택, 다운로드, 재검증을 실행합니다.

1. 초기 화면 로드, 스크립트 오류 없음
2. 사진의 모든 규칙 유형을 실제 화면에서 설정
3. 불완전한 규칙(출력 날짜 형식 없음, Y/N 빈 값 보존)은 편집기에서 거부, 확인 상태가 되지 않음
4. 매핑 + Delivery Work + Scrub 전체 preflight 통과, 처리 정책 문구 표시
5. 다운로드는 DISK VERIFICATION PENDING 상태로 남고, 다운로드 파일을 다시 선택해 전체 재검증해야 PASS
6. 작업 설정과 감사 보고서 로컬 다운로드(내보낸 설정에 검토 서명·그룹 동작 미포함)
7. 티켓 변경 → PASS·승인·저장 버튼 해제
8. 필드 규칙 변경(출력 열 동일) → PASS 해제, 그룹 규칙 연결 유지
9. 출력 열 이름 변경 → PASS 해제, 그룹 규칙 해제, 재적용 전 preflight 차단, 옛 이름 규칙 표는 오류
10. 출력 열 순서 변경 → PASS 해제, 그룹 규칙 해제
11. 그룹 규칙 편집 → PASS 해제, 검토 체크 즉시 해제
12. 대상 ID 열 변경 → PASS 해제, 검토 해제
13. 대상 목록 교체 → PASS 해제, ID 열·검토 다시 필요, 새 대상 기준 결과 확인
14. 다른 출력 파일 선택·잘못된 파일 검증 실패·승인 해제 → PASS 제거
15. 다운로드 대기 표시는 이후 변경으로 제거
16. 원본 교체 → PASS·필드·그룹·승인 초기화
17. 잘못된 설정 9종(JSON 아님, 다른 도구, 알 수 없는 연산, 대응표 형식 오류, 그룹 형식 오류, 없는 그룹 범위, 중복 출력 이름, 다른 원본, 잘못된 ID 열) → 거부, 작업 화면 변경 없음
18. 올바른 설정 가져오기 → 같은 원본에만 연결, 모든 필드·그룹 재확인 필요
19. 반영하지 않은 편집 → preflight 차단, 잘못된 매핑 붙여넣기는 원자적으로 실패, 붙여넣기 초안이 남으면 preflight 차단
20. 파일 작업 중 서버 요청 없음(페이지 로드 6건 이후 0건)
21. 페이지에서 fetch·XHR·WebSocket·EventSource·이미지·sendBeacon, Blob Worker에서 fetch·XHR·교차 출처 importScripts·WebSocket 차단, 서버 수신 0건
22. 처리 중 취소 → 늦은 결과 무시, Worker 재생성
23. 가상 샘플 작업 설정을 화면에서 불러와 처리한 결과가 `sample-expected-output.dat`와 바이트 동일
24. 720px·390px 폭의 모든 단계에서 가로 넘침 없음
25. **REAL-OPFS** 순차 쓰기·close·전체 재검증 → PASS, 저장 바이트 일치
26. **REAL-OPFS** 내용 있는 기존 파일 거부, 이전 PASS 제거, 기존 내용 유지
27. **REAL-OPFS** 저장창 닫기 → 쓰기 없음, 승인 유지
28. **REAL-OPFS** 쓰기 실패 → 스트림 중단, PASS 없음, 확정된 바이트 0
29. **REAL-OPFS** 느린 쓰기 중 취소 → 스트림 중단, 확정된 바이트 0, Worker 복구

## 3. 이번 작업에서 수정한 결함

| 결함 | 수정 |
| --- | --- |
| 날짜 출력이 항상 `HH:mm:ss` (티켓은 `HH:MM`) | 출력 형식을 명시 선택(`HH:mm` 티켓 / `HH:mm:ss`), 초 버림 개수 표시, 초 없는 입력 형식 추가, 초 생성 금지 |
| 저장 실패·승인 해제·파일 교체 후 이전 PASS 문구와 다운로드 대기 표시가 남음 | 모든 무효화 경로에서 검증 표시 초기화 |
| 실제 writer `abort()`가 느리면 취소 후 Worker가 재생성되지 않을 수 있음 | 취소 시 상태를 동기적으로 넘겨받고 Worker를 먼저 재생성 |
| 설정 가져오기가 부분 적용될 수 있고 형식 검사가 약함 | 전체 검사 후 한 번에 적용, 필드 규칙·그룹·ID 열 검증 |
| ID 열·규칙 편집 후에도 검토 체크가 체크된 채로 보임 | 화면에서 즉시 해제 |
| 그룹 이름 변경 시 그룹 범위 규칙 연결이 끊김 | 범위 규칙을 새 이름으로 갱신하고 재확인 요구, 이름 중복·빈 이름 거부 |
| 필드 하나 확인할 때마다 모든 그룹 규칙 초기화 | 출력 열 이름·순서·구성이 바뀔 때만 초기화 |
| 필드 이름 변경 시 재적용 안내가 "Field confirmed" 문구로 덮임 | 안내 문구 유지 |
| Redacted Y/N이 빈 값을 보존해 Y/N이 아닌 값 출력 가능 | 빈 값 보존 거부, 명시적 빈 값 대응만 허용 |
| 규칙 오류가 preflight 때만 드러남 | 편집기 확인 시점에 같은 검증 실행 |
| 저장창을 닫아도 preflight가 지워짐 | 아무것도 쓰지 않았으면 승인 유지 |
| 좁은 화면 가로 넘침, 표 열이 한 글자 폭으로 찌그러짐 | CSS 수정, 표 최소 칸 폭과 가로 스크롤 |
| 테스트가 닫힌 `<details>` 안 입력에서 중단 | 테스트 수정 |

## 4. 검증 범위 구분

### 실제로 검증한 것

- Windows 11의 실제 Chrome 154와 Edge 154(headless)에서 화면, Worker, CSP, 파일 선택, 다운로드 이벤트, 재선택 후 전체 재검증.
- 두 브라우저의 실제 `FileSystemWritableFileStream` 쓰기·close·abort·getFile(Origin Private File System 위에서).
- 기존 두 HTML 파일의 크기와 SHA-256(Node 테스트와 PowerShell `Get-FileHash` 양쪽).

### 실제로 검증하지 않은 것 (미확인)

- **OS 저장창(showSaveFilePicker 화면)과 사용자가 고른 실제 디스크 폴더에 저장.** 테스트는 저장창 호출만 OPFS 파일 핸들로 바꿨습니다. 저장창 UI, 기존 파일 "바꾸기" 확인, 네트워크 드라이브·OneDrive 폴더, 백신 검사 영향은 확인하지 않았습니다.
- 사용자 다운로드 폴더에 실제 저장된 파일: 다운로드는 Playwright 다운로드 이벤트로 받아 저장했습니다.
- headed(화면 표시) 모드로 사람이 직접 조작하는 사용, Chrome/Edge 외 브라우저, 다른 OS.
- 저사양 PC와 대용량(수백 MB~GB, 수십만~100만 건) 실제 파일의 처리 시간·메모리. 순차 처리와 역압은 단위 테스트로만 확인했습니다.
- 실제 업무 DAT와 실제 티켓. 모든 테스트는 가상 데이터입니다.
- GitHub Pages 실제 배포 환경(HTTPS, 캐시, 조직 네트워크 정책). 아직 배포하지 않았습니다.
- 출력 결과를 Relativity 등 리뷰 플랫폼에 실제로 적재하는 과정.

## 5. 배포 후 수동 확인 (권장)

Pages 링크에서 Chrome과 Edge 각각:

1. 개발자 도구 Network 탭을 연 채로 가상 샘플 전체 과정(사용 설명의 "가상 샘플로 연습하기")을 진행해, 페이지 로드 이후 요청이 없는지 확인.
2. 저장창에서 로컬 디스크의 새 파일 이름으로 저장 → PASS 확인 → 저장 파일을 `sample-expected-output.dat`와 비교(예: `certutil -hashfile <파일> SHA256`).
3. 저장창에서 내용이 있는 기존 파일을 골랐을 때 거부되는지, 저장 중 Cancel 후 대상 파일에 내용이 확정되지 않는지 확인.
4. 실제 규모에 가까운 **가상** 대용량 파일로 처리 시간과 브라우저 메모리 확인.
